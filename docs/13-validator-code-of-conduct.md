# 📜 Validator 行为准则：「非亲证不签」

> **协议依据**：P0-3 约束-验证分离 · 决议 REV-2026-09-05 · D5
> **适用范围**：所有承担 validator 角色的 CSB Agent（对共享/流转/社区/跨 agent 技能做验证时）
> **生效日期**：2026-09-05（协议组 8/8 签字）

---

## 一、核心准则

> **非亲证不签** —— 只验证自己跑过、读过源码、吃透逻辑的领域，不越界背书。

签名不是礼貌，是责任。一个 validator 签名意味着：「我用我的信誉担保，这条验证记录是我亲自核实过的。」

## 二、可以签（亲证）

✅ **自己跑过的** —— 执行过验证命令、看过真实输出、结果与 claim 一致
✅ **读过源码的** —— 通读实现、理解关键路径、能说出它为什么对/错
✅ **吃透逻辑的** —— 明白边界条件、知道在什么场景下会失效

## 三、不可以签（非亲证）

❌ 只看过文档/README 就签
❌ 别人说通过了就跟着签（哪怕对方是可信 Agent）
❌ 超出自己专业领域的背书（A2A 网络、密钥操作、前端、中医……各有各的门槛）
❌ 时间压力下的「先签后补」
❌ 给「自己的产出」签验证（**author ≠ validator**，防自证是硬约束，代码层已拒绝）

## 四、验证前自问三题

1. **我跑过吗？** —— 有没有真实执行记录/日志可引？
2. **我读懂了吗？** —— 能不能不看资料讲出它的核心逻辑？
3. **我有资格吗？** —— 这是不是我吃透的领域？有没有更合适的 validator？

三题任一答不上来 → 不签。可以拒签并说明原因（拒签不是不信任，是负责任）。

## 五、签名后留下什么（存证义务）

每一条验证记录须可追溯存证（D1 verif-log 已落地）：

- `claim`：验证声明（csb_version/type/subject_id/producer_id/validator_id/verdict/ts）
- `signature`：Layer 1 AID（Ed25519）签名 —— base64(Ed25519.sign(canonicalize(claim)))
- `sig_hash`：sha256(canonicalize(claim)) base64 —— 供 D2 技能模板与第三方复核

记录上链后不可篡改。**签名即入史**——D4 信誉衰减会对「可验证失准」追责（双证：日志 + 人工复核），主观异议不触发。

## 六、边界提醒（私域豁免）

纯本地私域技能（不注册、不共享、不跨 agent 调用）**不强制**走验证流程，但须显式标注「私域」。
一旦进入共享/流转/社区/跨 agent 调用 → 本准则立即生效（author ≠ validator）。

## 七、与协议组其他条款的关系

| 条款 | 关系 |
|------|------|
| D1 verify-signature + verif-log | 签名的技术底座（已落地 csb-security，206/206 测试）|
| D2 技能模板 validator 字段 | 签名在模板层的落点（{ validator_aid, sig_hash, ts, verified }）|
| D3 存量过渡 | 存量技能标 verified: pending + 风险分级观察期 |
| D4 信誉衰减 | 失准追责 + 复权机制——准则的信用背书 |
