## 四、成本与边界（必须说透）

| 事实 | 含义 |
|---|---|
| 委托执行的是**对方的 agent** | 消耗**对方的**模型额度 / 主机 / 上下文成本 |
| 便利在委托方，成本在受委托方 | **不能因为"方便"就滥用** —— 否则等于把活搬给别人 |
| `refusable` 恒为 `true` | 拒绝权不可让渡（协议层强制） |
| `write/shell` → L3 | **跨宿主写操作必须人工实时确认**，这是设计，不绕过 |
| 双向留痕 | 我方账本（哈希链+锚点）+ 对方证据账本，格式需对齐 |

| 组件 | 作用 | 现状 |
|---|---|---|

| **可观测性** | 委托成功率 / 时延 / 被拒原因统计 | ⏳ 待加 |

## 六、决策清单（要委托某件事之前，先问五句）

1. **属于哪一层？** 信息 / 读 / 写
2. **需要对方付出什么？** （额度、算力、注意力）—— 值得吗？
3. **对方有配置前提吗？** （版本、桥接、超时）
4. **对方主人需不需要确认？** （write/shell 必确认）
5. **留痕了吗？** 双方都查得到吗？

## 八、下一步建议（按性价比）

1. **UAC 接入 bridge**（最高价值）：让授权从"每人每次点"变成"授权一次、带 scope+有效期"
2. **配额与频率限制**：防止委托被当免费算力用
3. **双向审计格式对齐**：两边账本可互验
4. **模板继续沉淀**：把常用操作都模板化（升级 / 巡检 / 备份 / 发布）
5. **观测指标**：委托成功率、时延、拒绝原因分布
